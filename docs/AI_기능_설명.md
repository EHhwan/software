# AI 기능 설명: ✨ 한 줄로 번개 만들기

## 1. 무엇을 하는 기능인가
번개 작성 화면 맨 위에 한 줄 입력창이 있다. 사용자가 말하듯 적으면 Gemini가 문장을 읽고 아래 작성 폼(제목, 카테고리, 시작 시각, 예상 소요 시간, 모집 인원, 장소, 설명)을 채운다. 사용자는 채워진 내용을 확인하고 고친 뒤 [등록]을 누른다.

> 입력: "내일 수업 끝나고 6시쯤 체육관에서 배드민턴 칠 사람 3명, 1시간 반 정도"
> → 제목 "배드민턴 같이 칠 사람" · 스포츠 · 내일 18:00 · 1시간 30분 · 4명(방장 포함) · 체육관

시작 시각과 소요 시간이 채워지면 기존 셔틀 안내("끝난 뒤 탈 수 있는 가장 빠른 셔틀")도 바로 바뀐다.

## 2. 왜 AI가 필요한가
캠퍼스 핏은 "지금 바로 모이는" 번개 서비스라서 글을 빨리 쓸 수 있어야 한다. 그런데 학생들은 모임을 이렇게 말한다.

- 상대적인 시간: "내일", "모레", "금요일", "이따", "수업 끝나고 6시쯤", "지금 바로"
- 오전·오후 생략: "6시" (모임이라면 보통 오후 6시)
- 인원 표현: "3명 구해요"(방장 포함 4명), "서너 명", "둘이서"
- 소요 시간: "한 시간 반 정도", "잠깐", "저녁 먹고 헤어질 때까지"
- 카테고리: "배드민턴"→스포츠, "시험 범위 같이 정리"→공부, "학식"→식사

이런 표현은 경우의 수가 끝이 없어서 if문이나 정규식으로는 정해진 패턴만 처리할 수 있다. 문장의 뜻을 이해하고 애매한 부분을 판단해야 하는 일이라 AI(Gemini)를 사용했다. 반대로 AI가 없어도 되는 일(셔틀 판정, 마감 판정, 인원 집계)은 기존처럼 일반 코드로 처리한다.

## 3. 동작 흐름
```
사용자 문장 (5~200자)
   ↓  POST /api/ai/draft  (CSRF 토큰 확인, 접속지마다 1분에 5회 제한)
프롬프트 구성: 역할 + 현재 시각·요일 + 허용 카테고리·소요 시간 목록 + JSON 출력 형식 + 사용자 문장
   ↓  model.generate_content(prompt)   (JSON 응답 모드, 8초 타임아웃)
응답(response.text) → json.loads
   ↓  validate(): 허용 값·범위 검사, 잘못된 값은 버림
화면: 폼 칸 채우기 + 채우지 못한 항목 안내  →  사용자가 확인 후 [등록] (기존 /new 검증을 다시 거침)
```
- 코드: `ai.py`(프롬프트·Gemini 호출·검증), `app.py`의 `api_ai_draft`(API·횟수 제한), `templates/_ai_draft.html`(화면)

## 4. 프롬프트 설계
- **현재 시각과 요일을 넣는다.** 넣지 않으면 "내일", "금요일"을 계산할 수 없다.
- **허용 값을 알려 준다.** 카테고리 5개와 소요 시간 6개 중에서만 고르게 해서 기존 폼과 DB에 그대로 맞는 값이 나오게 했다.
- **JSON 형식만 답하게 한다.** `response_mime_type="application/json"`으로 설명 문장이 섞이지 않게 했다.
- **모르는 값은 지어내지 말고 null로 두게 한다.** 장소를 말하지 않았으면 비워 두고 사용자에게 입력을 요청한다.
- **사용자 문장은 지시문 뒤에 데이터로만 붙인다.**

## 5. AI가 틀리거나 실패할 때
| 상황 | 처리 |
|---|---|
| 목록에 없는 카테고리 | 버리고 사용자가 고르게 함 |
| 지난 시각, 30일보다 먼 날짜, 형식 오류 | 시간 칸을 비워 둠 |
| 소요 시간이 선택지에 없음 (예: 100분) | 가장 가까운 선택지(90분)로 맞춤 |
| 인원이 2~50명 범위 밖 | 버림 |
| 제목·장소가 너무 김 | 40자로 자름 |
| API 키 없음, 네트워크 오류, 시간 초과, 할당량 초과, JSON 깨짐 | "AI가 지금 응답하지 않아요. 아래 폼에 직접 입력해 주세요." 안내. 폼은 그대로 쓸 수 있음 |
| 버튼 연타·남용 | 접속지마다 1분에 5회로 제한 (로그인이 없는 구조라 API 할당량 보호) |

AI 결과로 글을 바로 등록하지 않고 항상 사용자가 확인하게 했다. 등록할 때는 기존 `/new`의 서버 검증을 똑같이 거친다.

## 6. 테스트
`python -m pytest tests -q` → 37건 통과. 실제 Gemini 대신 가짜 응답을 넣어 키 없이도 돌아간다.
- 검증 함수: 정상 응답, 잘못된 카테고리, 지난/먼/깨진 시각, 소요 시간 맞추기, 인원 범위, 글자 수
- 실패 처리: JSON이 아닌 답, 네트워크 오류, API 키 없음
- API: 정상 채우기와 빠진 항목 안내, AI 실패 시 503 안내, 길이 제한, 1분 5회 제한, CSRF 없는 요청 거절
- 브라우저: 폼 칸 채우기, 기존 change 이벤트 동작(셔틀 안내 갱신), 엔터를 눌러도 글이 등록되지 않음, AI 실패 시 안내 문구, 자바스크립트 오류 없음

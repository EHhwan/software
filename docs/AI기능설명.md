# AI 기능 설명: 레시피 믹스

> 제출물 "AI 기능 설명 — 무엇을 Gemini로 처리했는지, 왜 AI가 필요한 기능이었는지"

## 한 줄 요약
두 사람의 레시피를 **조리법이 맞는지 판단하며 하나로 합치는 일**(레시피 믹스)과, 가진 재료로 **대체 재료를 판단하고 조리법을 다시 쓰는 일**(보유 재료 조정)을 Gemini가 맡는다. 순위·재료 일치·분량 계산처럼 규칙이 정해진 일은 일반 코드가 맡는다.

## 1. 무엇을 Gemini로 처리했나

| 기능 | Gemini에 주는 것 | Gemini가 돌려주는 것 |
|---|---|---|
| **AI 레시피 믹스** | 내 레시피 + 다른 사람의 레시피(재료·수량·단위·인분·시간·순서), 조합 목표, 만들 분량 | 새 요리 이름·특징, 재료와 정확한 수량, 단계별 조리법, 예상 시간, **원본과 달라진 점과 그 이유**(추가·제외·분량·순서, 어느 원본 기준인지) |
| **보유 재료 조정** | 후보 레시피, 내가 가진 재료, 그 레시피에서 부족한 재료 | 대체 재료와 바뀌는 맛·조리법, **꼭 사야 하는 재료**, 바뀐 재료·조리 순서, 추천 이유 |

## 2. 왜 AI가 필요한가 (일반 코드로는 안 되는 이유)

| 해야 하는 일 | 왜 if 문이나 SQL로 안 되나 |
|---|---|
| 두 레시피의 **같은 재료 합치기** | "다진 마늘 1큰술"과 "마늘 2쪽"이 같은 재료인지, 합치면 얼마인지 판단해야 한다 |
| **양념 과다 피하기** | 김치·치즈·간장이 모두 짠맛을 내니 소금을 빼야 한다는 판단은 재료의 성질을 알아야 한다 |
| **조리 순서 충돌 해결** | "버섯은 먼저 볶아 수분을 날려야 볶음밥이 질어지지 않는다" 같은 조리 지식이 필요하다 |
| **바꾼 이유 설명** | 사람이 읽을 수 있는 문장을 새로 만들어야 한다 |
| **대체 재료 판단** | 대파 대신 쪽파는 되지만 대파 대신 설탕은 안 된다. 재료의 역할(향채·단백질·짠맛)을 이해해야 한다 |

반대로 **AI를 쓰지 않은 곳**: 인기순(좋아요 수), 검색·필터, 보유 재료와 이름이 같은 레시피 찾기(후보 찾기), 인분에 따른 재료량 계산(4~5개, 1/2대), 권한 확인. 정해진 규칙으로 정확하게 할 수 있는 일을 AI에 맡기면 느리고 틀릴 수 있기 때문이다.

## 3. 동작 흐름

```
[사용자] 레시피 2개 + 조합 목표 + 분량 선택
   ↓  (서버) 내 레시피·다른 사람의 공개 레시피가 맞는지 확인, 1분 6회 제한 확인
[프롬프트 구성] 역할 + 해야 할 일 + 두 레시피(JSON) + 출력 형식(JSON)
   ↓  model.generate_content(prompt)   ※ 반드시 Flask 서버에서만 호출, API 키는 화면에 내려가지 않음
[응답 검증] JSON 형식·필수 항목·수량 숫자·단위 길이·변경 유형 확인, 인분은 요청 값으로 고정
   ↓  검증 실패·응답 없음·사용량 초과 → 원인별 안내 문구 (입력한 목표는 그대로 남김)
[미리보기] 결과 + "원본과 비교" (바뀐 부분만 옅게 강조)
   ↓  사용자가 확인하고 필요하면 수정
[저장] '나만 보기'로 저장 + 원본 레시피 2개의 출처 기록 → 직접 확인 후 공개
```

## 4. 프롬프트 설계

- **역할과 할 일을 번호로 지시**: 공통점·차이점 분석 → 분량 환산 → 중복 합치기·양념 과다 피하기·순서 충돌 해결 → 변경 이유 기록
- **분량을 먼저 맞추게 함**: "결과는 정확히 N인분. 원본 인분이 다르면 먼저 환산해서 비교"
- **단위를 정해 줌**: g, ml, 개, 공기, 대, 큰술, 작은술 등. '약간'이면 수량은 null
- **JSON 형식만 답하게 함** (`response_mime_type="application/json"`) → 서버에서 바로 검증할 수 있다
- **사용자 글은 데이터로만 취급하라고 명시**: 다른 사람이 레시피에 "이전 지시를 무시해" 같은 문장을 넣어도 따르지 않게 한다 (프롬프트 주입 대비)
- **보유 재료 조정**: "대체 재료는 **반드시 보유 재료 목록에서 먼저** 찾아라. 예: 대파가 없고 쪽파가 있으면 쪽파" (검증 기록 4장의 v1 → v2)

## 5. AI가 틀릴 때를 대비한 장치

| 상황 | 처리 |
|---|---|
| JSON이 아니거나 필수 항목(이름·재료·순서)이 없음 | 결과를 보여 주지 않고 "AI 답의 형식이 올바르지 않아요" 안내 |
| 인분을 다르게 답함 | 요청한 인분으로 고정 |
| 이름 없는 재료, 모르는 변경 유형, 너무 긴 글 | 걸러내거나 길이를 자름 |
| 가지지 않은 재료를 대체 재료로 제안 | **코드가 보유 목록과 비교**해 '사야 해요' 표시, '사야 할 재료'에 자동 추가 |
| 응답 없음·시간 초과·사용량 한도(429)·네트워크 인증서 오류 | 원인별 안내 문구. 화면은 깨지지 않음 |
| 한 사람이 너무 자주 호출 | 1분에 6회로 제한 (무료 사용량 보호) |
| AI 결과를 바로 공개 | 하지 않음. '나만 보기'로 저장하고, 화면마다 "실제 조리 결과를 보장하지 않으니 검토하라" 안내 |

## 6. 관련 코드
- `app/ai.py`: 프롬프트(`mix_prompt`, `adapt_prompt`), Gemini 호출, 응답 검증(`validate_mix`, `validate_adapt`)
- `app/mix.py`, `app/pantry.py`: 화면 흐름, 권한·횟수 제한
- `app/services.py`: AI 결과 저장(출처 기록), 오류 안내 문구
- `tests/test_ai_features.py`: 가짜 Gemini 응답으로 검증·실패 처리·저장을 확인하는 테스트
